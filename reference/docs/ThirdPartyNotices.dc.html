Third-party notices — Offline AI NPC

Every third-party component the plugin touches: the dependencies you install, the external processes it drives, and the model and voice files it downloads or lets you point it at. Nothing third-party is bundled in the package itself — Assets/OfflineAINPC/ contains only the plugin's own code, documentation and these notices. Missing notices are a documented Asset Store rejection reason, so this file is kept current with every dependency change.

"Verified" column: the date the licence text was read at the source linked in the row. Where a dated copy is archived next to this file, the row says so.

Dependencies you install (never bundled)

Bundling either would give anyone who already has them duplicate-assembly compile errors, so the plugin declares them and compiles the code that touches them only when they are present (versionDefines on the package ids).

External processes the plugin drives (not redistributed)

Separate executables you install. The plugin starts, talks to, and shuts them down; it does not ship their binaries, and the export excludes anything that looks like one.

**The espeak-ng row decides whether a game built with this can ship Piper.** What "external process" has to mean in practice and what a buyer owes if they redistribute Piper are in ESPEAK_BOUNDARY.md. The package itself contains none of it.

Voice models (downloaded by the Presets window or supplied by you, not shipped)

What the package export contains

Tools ▸ Offline AI NPC ▸ Export .unitypackage… takes everything under Assets/OfflineAINPC/ except Tests/ and the packaging tools. A test in the source repository fails if an engine binary, an espeak-ng-data/ folder, or a .onnx / .gguf file ever appears under the package folder, so none of the components above can travel by accident.
